## 공유 방법

- `config/company-info.json`: 회사 필드의 값·확인 상태·증거와 승인자/일자. 사업자 원본이나 개인정보 원문을 이 공개 저장소에 넣지 않는다.
- `scripts/company-info.mjs`: 공통 footer 렌더러 및 승인 검증. 내용은 정적 HTML로 반영하며 브라우저가 설정 파일을 요청하지 않는다.
- `scripts/sync-company-footer.mjs <명시적 HTML 경로...>`: 의도한 위치의 footer 스냅샷과 공통 CSS를 갱신한다. 루트와 하위 공개 페이지가 같은 데이터로 생성된다.
- 빌드 때 표시된 공통 footer를 재생성한다. Organization JSON-LD의 법인·주소·연락처·번호 등 미확정 주장은 제거하고 브랜드명만 유지한다. 승인 상태와 확인된 증거가 갖춰진 필드만 복원한다. Service의 서비스 설명은 변경하지 않는다.
- `config`, `docs`, `scripts`, `tests`는 정적 배포 allowlist 밖이다. 브라우저용 화면에 내부 `NEED VERIFY` 목록이나 원본 증거를 내보내지 않는다.

FLOW의 현재 운영 원본 `SiteFooter.tsx`에는 ‘운영·관리 Mashcore’가 있고 법률 링크가 없다. 이번 패치에서 FLOW runtime과 기존 독립 Field Notes 번들을 변경하지 않았다. 홈페이지의 Field Notes에 공통 외부 footer를 추가했으므로 기존 SPA 내부 footer와 중복 표시 가능성이 남는다. FLOW 원본 공통 footer와 공개 번들을 함께 검토·빌드하는 후속 변경으로 법인 표시를 일치시켜야 한다. 외부 footer 추가만으로 FLOW 전체 동기화가 끝났다고 판단하지 않는다.

## 승인 후 확정 절차

1. 최신 등록증 및 담당자의 확인으로 법인명·대표자·번호·주소를 대조한다. 연락처의 실제 관리 주체와 개인정보 권리요청 부서/연락처를 지정한다. 공개 가능한 증거 식별자만 config에 적고 원본 증빙은 권한 있는 보관처에 둔다.
2. 각 필드의 `status: confirmed`, 비어 있지 않은 `value`, `evidence`를 채운다. 승인자·실제 승인일을 기입한다. 모든 필드가 검증되어도 최종 운영 배포 승인이 자동으로 생기지는 않는다.
3. 개인정보 처리 흐름과 방침을 함께 승인한 뒤 회사/방침의 `publicationState`, `releaseApproved`, 승인 기록을 갱신한다. 임의의 값이나 문자열 `"true"`로 통과할 수 없다.
4. footer 스냅샷·Organization JSON-LD·FLOW 원본 표시를 대조한다. 별도 브랜치/PR에서 미리보기를 검수하고 사용자의 최종 승인 뒤 운영 반영한다.

Mashcore는 현재 `https://mashcore.netlify.app/about/`로 연결한다. 계정 공유, 상담정보 전달, 처리위탁 관계를 의미하지 않는다. 통신판매업 표기와 결제 고지는 실제 거래 방식·적용 여부가 확인된 뒤 검토하며, 신고번호나 약관을 만들지 않는다.
