# v1.4 글로벌 서비스 시범 페이지 검토

기준: 2026-10-19 KST · PR #8의 v1.3 `95756243dce1e242a90970eb2c266508f331b2f0` 위에 추가. 운영 제공 범위 확정이나 공개 배포 승인이 아닌 Draft/Preview 구현이다.

## 구현 경계

- 기존 PR #5의 `en/index.html`, 번역 사전, 가격 자료, 빌더를 가져오지 않았다. `/en/global/` 이하만 독립적으로 작성했다.
- 한국어·영어 3쌍을 같은 검토 브랜치의 글로벌 단위로 분리했다. PR #5 병합이나 가격 승인이 아니다.
- 회사·개인정보 config, FLOW, 기존 인증/CRM/고객 접근 권한, 기존 API, 계약/결제, 분석 이벤트를 변경하지 않았다.
- 이 페이지들에는 폼·입력란·실행 JavaScript·언어 감지·자동 리디렉트·개인정보 저장이 없다. 사용자가 펼치는 native `details`와 실제 링크만 사용한다.
- 새 CSS는 시스템 글꼴을 사용하며 외부 폰트·라이브러리를 추가하지 않는다. 120ms 버튼 눌림만 있으며 OS의 reduced-motion에서는 제거한다.
- 영문 원고는 영문 사업자 독자에 맞춰 새로 편집했다. **외부 원어민과 현지 운영자의 검수는 미완료**다.

## URL과 실제 언어 쌍

| 한국어 | 영어 | 대상 |
|---|---|---|
| `/global/` | `/en/global/` | 두 서비스 방향을 고르는 매장 운영자 |
| `/global/international-visitors-korea/` | `/en/global/international-visitors-korea/` | 외국인 고객을 유치하고 싶은 한국 매장 운영자 |
| `/global/korean-visitors-overseas/` | `/en/global/korean-visitors-overseas/` | 한국인 고객을 유치하고 싶은 해외 현지 매장 운영자 |

각 페이지의 `lang`, 고유 title/description, 자기 canonical, ko/en 상호 `hreflang`, 같은 쌍의 ko를 가리키는 `x-default`, 수동 언어 전환, OG URL/locale, WebPage JSON-LD를 명시했다. A/B 시장은 서로 번역쌍으로 연결하지 않는다. 영어 `/en/`을 전제로 하는 링크도 없다.

canonical은 향후 검토할 운영 URL `https://withweplace.kr`을 사용한다. 현재 운영 경로가 공개됐다는 주장이 아니다. 모든 시범 원본에 `noindex,nofollow`를 명시한다. Preview의 빌드 헤더/robots와 sitemap 정책은 통합 검수에서 함께 확인한다. noindex는 비밀정보 접근 통제가 아니며 이 페이지에 고객 자료나 개인정보를 넣지 않았다.

## 두 시장의 차이

| 항목 | 한국 매장 → 외국인 방문 | 해외 매장 → 한국인 방문 |
|---|---|---|
| 비용을 검토하는 고객 | 한국에서 사업하는 대표·운영자 | 해외 현지에서 사업하는 대표·운영자 |
| 페이지 속 손님 | 한국 방문 예정자 또는 국내 체류 외국인 | 여행 전후 한국어로 정보를 찾는 여행객 |
| 첫 장면 | 메뉴 사진 다음에 가격과 예약 방법이 궁금한 식당 손님 | 케어 서비스의 포함 항목과 찾아가는 길이 궁금한 여행객 |
| 확인할 정보 | 메뉴 단위·추가 비용, 지도/입구, 문의 언어와 예약 확정 | 현지 통화·포함 항목, 현지 상호/주소/지도, 예약·변경·준비 사항 |
| 플랫폼 검토 | 매장 홈페이지와 운영자가 관리하는 Google 지도 등 | 한국어 홈페이지·네이버 등 한국어 검색과 현지에서 이용할 지도 |
| 운영자에게 확인 | 실제 메뉴/가격·언어·운영시간·채널 소유권 | 현지 운영 조건·국가별 계약/정산·응대 언어·채널 소유권 |
| 확정하지 않은 것 | 국가/언어별 제공, 촬영·제작·출장 범위, 일정·비용 | 지원 국가, 현지 법/계약/정산, 언어 검수, 담당자·일정·비용 |

국가명·해외 지점·고객 실명·고객 성과·추천 후기·확정 가격·예약 가능 시간은 생성하지 않았다. 페이지의 언어(ko/en)와 실제 서비스/상담/현장 응대 언어를 구분했다.

## 문장과 장면의 편집 대장

신규 페이지이므로 아래의 '출발점'은 기존 사이트 문구가 아니라 첨부 설계서의 제안 문구다. 기존 사이트를 수정한 대장과 혼동하지 않는다.

| 화면 | 출발점/의도 | 적용 문장 | 편집 이유·사실 등급 | 다음 행동 |
|---|---|---|---|---|
| 글로벌 소개 H1 | 글로벌 두 시장을 소개 | 언어가 달라도, 방문을 결정할 답은 필요합니다. | 기술 약어 대신 손님이 확인하는 일로 시작 · 서비스 설명 |
| 국내 매장 카드 | 한국의 좋은 매장, 외국인 손님에게도 제대로 전해지도록. | 외국인 손님이 우리 매장에 오기까지. | 운영자와 손님의 방향을 짧게 구분 · 서비스 검토안 |
| 해외 매장 카드 | 해외에 있는 매장도, 한국인 여행객에게 선택받을 수 있도록. | 한국인 여행객이 우리 매장을 고르기까지. | 국가별 서비스 확정 없이 대상 손님을 명시 · 서비스 검토안 |
| 한국 매장 상세 장면 | 외국인 검색→메뉴→예약 | “이 메뉴는 얼마이고, 예약은 어디에서 하나요?” | 식당 상황의 두 실무 질문 · 가상 장면 |
| 해외 매장 상세 장면 | 현지 가격/위치/예약 | “이 가격에 무엇이 포함되고, 어떻게 찾아가나요?” | 케어 서비스의 포함 항목·도착 차이를 구체화 · 가상 장면 |
| 공통 범위 | 국가/언어/운영 가능성 확인 | 번역할 문장보다, 확인할 운영 조건부터. | 페이지 번역과 실제 응대 능력을 혼동하지 않게 설명 · 확인 절차 |
| 영어 안내 | 직역 대신 사업자 관점 | Help international visitors find their way to you. / Help Korean travelers choose your business. | 언어가 아니라 고객 방향으로 두 경로 구분 · 원고 초안 |
| 문의 | 개인정보 자동 인입 금지 | 매장이 있는 지역과 업종, 손님이 자주 묻는 질문 한 가지를 준비해 주세요. | 연락 전 준비할 내용만 제안. 사이트에서 수집하지 않음 · 구현 확인 |

본문은 17px, 좁은 화면의 보조 문장도 기본 15px를 유지한다. 보조 FAQ는 `details`에 넣었지만 서비스 검토 상태, 수동 문의 CTA, 개인정보 링크, 법인 정보 검토 상태는 접지 않았다.

## 표시 데이터와 예시

- 도형의 방향은 '어떤 손님이 어디에 있는 매장을 찾는가'를 나타낸다. 지도상의 위치·거리·방문 수·성과를 나타내지 않는다.
- Before/After 형식의 두 장면은 가상의 안내다. 실제 고객 프로젝트·납품·성과가 아니라는 설명을 비교 화면 바로 위에 배치했다.
- 숫자 차트·성장률·가격표·검색량·키워드 난도·전환율을 추가하지 않았다.
- WebPage JSON-LD만 사용한다. LocalBusiness, 지점, 주소, 리뷰, 평점, 제공국가, Offer/가격 등의 구조화 데이터가 없다.
- keyword map과 실제 데이터 승인은 별도 `docs/v14-global-geo-keyword-map.md`, `docs/v14-chart-data-contract.md`에서 관리한다.

## 문의·회사 정보·개인정보

카카오 URL은 기존 공통 config와 같은 `https://pf.kakao.com/_mxbexhX`, 이메일은 기존 `weplace25@gmail.com`이다. 메일 body/subject나 URL query에 서비스·국가·선택값을 자동으로 싣지 않는다. `/meeting/`도 쿼리 없이 이동한다. 링크 클릭과 상담 접수는 구분한다. 도착 페이지의 실제 전송은 방문자 본인이 수행한다.

영문 페이지의 미팅/개인정보 링크는 목적지가 한국어임을 링크 이름에 명시했다. 생성되는 회사 정보 푸터를 수동 번역하거나 새 법인 사실을 만들지 않았다. 기존 `WEPLACE_COMPANY_FOOTER` 블록 전체를 보존하고 외부 `lang="ko"` 컨테이너와 영어 언어 안내를 사용한다. 추후 공식 영문 법인 정보가 검증되면 공통 생성기의 검토된 언어별 렌더링으로 확장할 수 있다.

6개 페이지의 공통 푸터는 `renderCompanyFooter()`와 완전 일치함을 로컬 DOM 검사로 확인했다. 최종 build는 기존 config로 재생성하므로 승인 게이트가 유지된다.

## 직접 실행한 정적 검사

- Node/jsdom으로 6개 페이지를 각각 로드: 언어 ko/en, H1 각 1개, 올바른 자기 canonical, 짝 페이지 링크를 확인했다.
- 6개 페이지에서 `form/input/textarea/select` 0개, 실행 스크립트 0개, JSON-LD 스크립트만 존재한다.
- overview마다 native `details` 1개, 시장 상세마다 2개다. 내용은 정적 HTML에 들어 있어 JavaScript와 무관하게 읽을 수 있다.
- 공통 법인 푸터 snapshot 6개가 생성기 결과와 일치한다.
- 실제 브라우저의 6개 폭·키보드·200% 확대·no-JS·reduced-motion·링크 도착은 전체 Preview 검수 기록에 합친다. 이 문서의 정적 검사를 실제 기기 검수로 표시하지 않는다.

## 통합할 항목과 최종 승인 대기

1. 메인 체험 아래 두 경로 진입, review viewer 경로, 빌더 정적 파일 복사, 링크 검사를 연결한다.
2. 시범 페이지는 noindex 상태다. 운영 sitemap 포함/검색 허용은 서비스 범위·언어 원고·법률 운영 검토와 운영 배포 승인 후 별도 결정한다.
3. 독립 영어 `/en/`이나 PR #5를 합치려면 메뉴, canonical, sitemap, 빌더 및 미확정 가격을 다시 비교한다.
4. 국가별 수요·실제 검색어/검색량·구매 의도 성과는 계정 데이터로 검증하지 못했다. 키워드 우선순위는 현재 가설이다.
5. 외부 원어민, 현지 매장 운영자, 실제 문의 담당자의 언어·제공 범위 확인이 필요하다.
6. 국외 이전·수탁자·계약/정산·해외 고객 권리 등 실제 운영 조건 검토가 필요하다. 법률 검토 완료로 표시하지 않는다.

롤백은 이 문서, 신규 글로벌 6페이지와 전용 CSS, 통합 진입 링크를 한 단위로 되돌린다. 기존 v1.3 체험·FLOW·PR #5에는 의존하지 않는다.
