## 실제 여백 확인

360px 렌더에서 header의 텍스트와 아래 테두리 사이 약 29px, landing-foot 위쪽 약 25px, hero-foot 약 30px/18px를 확인했다. 03·04·06 섹션 텍스트의 위 여백은 약 81px이며 좌우도 최소 약 21px다. 진단서 세 행의 아래 텍스트 여백은 각각 약 24px다. 정적 탐지는 flex 정렬, 내부 wrapper 및 padding-block을 충분히 계산하지 못했다.

별도 브라우저 비교에서도 360·1440px 버튼·링크의 텍스트가 테두리 4px 이내에 닿는 경우는 없었다. 신규 모바일 차트 버튼은 140×44px이며 실제 글자 여백은 최소 약 13px다. 진단 CTA의 좌우 여백은 모바일 19px, 데스크톱 23px다.

## 예외와 보존 범위

`impeccable hooks ignore-value`로 아래 두 규칙만 `.work/hero-evidence-polish-r3/unified-r3-hero-polish-r3.html`에 한정해 원래 작업 공간의 `.impeccable/config.json`에 기록했다.

- `buried-raster`: 선택되지 않은 사진이 숨겨지는 정상 동작.
- `cramped-padding`: 위 실측으로 확인한 여백 탐지 오탐 8건.

전체 파일 무시, 전역 규칙 무시, 작은 글씨 경고 억제는 하지 않았다. 기존 작은 글씨까지 확대할지는 사용자에게 선택을 요청했다. 답변 전에는 기존 화면 보존 범위를 유지한다.

이번 후속 검토에서는 UI·성과 수치·Preview 배포를 변경하지 않았다. 기존 빌드 및 166/299/149개 테스트 결과는 그대로 유효하다.
