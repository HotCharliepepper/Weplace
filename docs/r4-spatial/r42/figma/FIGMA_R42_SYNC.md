# WEPLACE R4.2 Figma 동기화 결과

검수일: 2026-11-03

## 실제 완료 범위

기존 Figma 파일 안에 R4.1 데스크톱·모바일 전체 화면을 복제한 뒤, R4.2 웹 소스의 브랜드·음식·안내 문구·Mashcore 연결을 편집 가능한 레이어로 반영했다. 기존 R4.1 원본 프레임과 글로벌 R4 변수의 값은 수정하지 않았다.

보존한 원본은 desktop `3:2`, mobile `4:2`이다. R4.2는 각각 기존 데스크톱·모바일 페이지에 별도 프레임으로 배치했으며, 완료 후 작업 중 표시를 해제했다.

## 웹 구현과 일치시킨 변경

- 제공 사진 3에서 출발한 웹용 벡터 해석 로고를 실제 웹과 동일한 SVG로 가져왔다. 글자는 윤곽선이고 13개의 벡터가 유지된다. 정확한 원본 로고 파일을 추출했다고 주장하지 않는다.
- 데스크톱 헤더 로고 180px, 모바일 헤더 156px를 적용했다. 헤더·푸터는 같은 로고 컴포넌트의 인스턴스다.
- ink `#20352D`, trust/signal `#285247`, signal-text `#1F4439`, soft `#EAE7DF`, sage `#AAB69E`, gold `#C8A56B`, proof `#80602F`를 R4.2 변수 컬렉션으로 분리했다. 기존 paper `#F5F0E9`, white `#FFFDFA`, muted, line 변수는 재사용한다.
- 기존 예시 관리실 사진을 루위 제공 베이징덕 이미지로 교체했다. 동일 1254×1254 원본을 두 페이지에 등록했고, 사진은 비트맵 이미지 채우기이며 나머지 UI는 편집 가능한 레이어다.
- 탭은 `외관 먼저 / 메뉴 먼저`, 기본 상태는 메뉴 먼저다. 안내 제목은 `먹고 싶은 메뉴에서, 예약할 자리까지.`, 질문은 `대표 메뉴 / 식사 자리 / 예약 안내`로 일치시켰다.
- 사진 출처와 화면 예시의 구분을 본문에 표시했다: `사진은 루위의 기존 제공 자료입니다. 아래 안내와 버튼은 화면 구성 예시이며, 사진 선택의 매출 효과를 뜻하지 않습니다.`
- 예약 영역에 `예약 안내 구성 예시 · 실제 예약 불가`를 표시했다.
- Mashcore 연결 제목·설명과 실제 URL `https://mashcore.co.kr/about/#weplace`를 반영했다.
- `2,100만 원`, `+12.2%`, `1.72억 → 1.93억`, 비교 기간, 관측값 주의 문구, 진단 `0원`, `매장 1곳 · 공개 채널 1개 · 직접 써볼 개선안 1개`를 보존했다.

## 대조한 설계와 보존 원칙

R4.1 디자인 context와 화면, FigJam의 R4 7개 장면 및 디자인→구현→GSAP→QA→Preview 흐름을 확인했다. Hero의 사실 기반 비교, Store의 사진→설명→예약 3개 레이어, FLOW의 역할별 구조를 유지했다. 디자인 수정은 이번 브랜드·음식 정리 범위에 한정했다. 내부 작업자의 달성률·연락 주기·추천 작업 같은 기능 확장은 이 프레임에 추가하지 않았다.

## 시각·구조 검수

데스크톱은 편집 가능한 텍스트 187개와 인스턴스 13개, 모바일은 텍스트 186개와 인스턴스 13개를 포함한다. 새 기본 질문·사진 선택 컨트롤은 재사용 가능한 컴포넌트이다. 전체 화면을 하나의 이미지로 붙인 결과물이 아니다.

첫 모바일 내보내기에서 사진이 비어 있었으며 해당 페이지의 실제 이미지 레이어에 자산을 직접 등록해 수정했다. 수정 후 모바일 음식 영역의 사진·캡션·질문 버튼·예약 문구가 렌더링되는 것을 확인했다. 데스크톱 음식 화면, Hero의 수치와 0 기준 차트, 모바일 헤더 로고와 Mashcore 문구, 전체 프레임 배치를 PNG로 확인했다.

자동 텍스트 확인은 두 프레임 모두 매출 수치, `0원`, 공개 채널 1개, 출처 캡션, Mashcore 문구의 존재를 통과했다. 기존 마사지 안내 제목이 음식 예시에 남지 않는 것도 확인했다.

## 정확한 제한

- 웹은 Pretendard를 사용한다. 연결된 Figma 환경에서 Pretendard를 사용할 수 없어 기존 Figma의 **Noto Sans KR** 대체 폰트를 유지했다. 따라서 글자 폭·줄바꿈·행 높이가 실제 브라우저와 완전히 같다고 주장하지 않는다. 새 로고는 윤곽선이므로 이 제한의 영향을 받지 않는다.
- 기존 Figma 전체 화면은 홈페이지를 축약한 설계 표현을 포함한다. 그 기반을 유지하면서 이번 핵심 변경을 동기화했으며, 모든 HTML 요소와 세부 간격을 1:1로 다시 만든 결과는 아니다. 실제 화면의 기준은 브라우저 캡처와 웹 소스다.
- 새 프레임은 메뉴 먼저·대표 메뉴를 기본으로 표시하는 편집 가능한 설계다. 외관 먼저/다른 질문 상태를 Figma 프로토타입의 동작으로 연결하거나 모든 상태를 별도 프레임으로 확장하지 않았다. 해당 동작과 GSAP·접근성 검증은 웹 구현과 테스트 결과에서 확인해야 한다.
- 원래 FigJam과 모션 스토리보드는 대조했고 보존했다. R4.2 별도 모션 스토리보드를 새로 작성하지 않았다.
