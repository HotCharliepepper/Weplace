# R4.2 독립 코드·자산 QA

검수일: 2026-11-03. 대상은 현재 작업 트리와 R4.1 기준 커밋 `cd860cb`입니다. 이 문서는 파일 대조·정적 코드 검토·명시한 테스트 실행 결과만 다룹니다. 브라우저 화면 검수, 배포 성공, 실측 성능 결과는 담당자가 별도 기록합니다.

## 1. 확인된 구현과 회귀 테스트

`node --test tests/main-r42.test.cjs`를 현재 소스로 다시 실행했습니다. 결과는 **5개 통과, 0개 실패, 0개 건너뜀**입니다. 기존 전체 테스트의 통과 여부를 이 결과로 대신하지 않습니다.

| 검수 대상 | 확인 결과와 한계 |
|---|---|
| 사진 전환 | 실제 before 이미지와 after 이미지의 src, srcset, alt, width/height를 함께 갱신합니다. before에서는 음식 srcset을 제거하고 after에서 복원합니다. 키보드 Home/End 전환을 DOM 테스트했습니다. |
| 예시 문구 | 사진 선택·질문·FLOW 예시 상태를 순회해 이전 마사지 문구가 다시 나타나지 않는지 검증했습니다. |
| JS 미사용 | 초기 HTML에 제공 사진, 예시 예약, 매출 효과 구분이 존재합니다. JS를 끈 실제 브라우저의 배치 검수는 별도입니다. |
| 진단 | 0원·매장 1곳·공개 채널 1개·개선안 1개의 기존 제공 범위를 유지합니다. 미확정 30만원 비교가격이나 인위적인 한정 인원을 추가하지 않았습니다. |
| 브랜드 | 로컬 SVG와 PNG/ICO 치수·프레임을 확인했습니다. 로고 HTML은 400×90, CSS는 비율을 유지하는 표시 크기를 사용합니다. |
| OG·SEO | review 빌드에서 HTTPS `*.netlify.app` 배포 URL만 새 R42 OG 이미지 원점으로 사용합니다. 잘못된 HTTP/유사 호스트를 거부하고 대체 DEPLOY_URL을 검증했습니다. canonical과 og:url은 유지합니다. 실제 URL 응답/소셜 크롤러 결과는 별도입니다. |

footer의 기존 `max-width:36px` 제약과 새 가로 로고가 충돌하지 않도록 `.w-brand.w-brand-r42 .w-logo-r42`에 `max-width:none`이 있습니다. 헤더 400:90 비율과 footer 크기 지정의 코드 적용을 확인했습니다. 다양한 화면의 시각 품질은 이 정적 확인만으로 판정하지 않습니다.

## 2. 색상 대비 수학 계산

현재 R42 토큰과 상속된 Paper/White/Muted의 불투명 단색 조합을 계산했습니다. sRGB 채널을 0~1로 바꾼 뒤 `c ≤ 0.04045`이면 `c/12.92`, 그 외에는 `((c+0.055)/1.055)^2.4`를 적용했습니다. 상대 휘도는 `0.2126R + 0.7152G + 0.0722B`, 대비는 `(밝은 휘도+0.05)/(어두운 휘도+0.05)`입니다. 비교 기준은 [W3C WCAG 2.2 Contrast Minimum](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)의 일반 텍스트 4.5:1, 큰 텍스트 3:1입니다.

|---|---|---|---:|---|

금색·세이지는 밝은 바탕의 작은 본문용으로 사용할 수 없습니다. 현재 금색 점과 면·테두리 장식은 텍스트 색과 구분하며, 금색 계열 본문용 토큰 `--proof`는 더 어두운 `#80602f`입니다. 상태를 색만으로 전달하지 않는지는 라벨·선택 상태와 함께 검수해야 합니다.

R42 body에 `--accent:var(--signal-text)`와 `--green:var(--trust)`가 직접 정의되어 있습니다. 상위 `:root`에서 계산된 이전 갈색 accent 값이 그대로 상속되는 문제를 방지하며, 포커스·hover·강조 숫자가 R42 토큰을 참조하도록 한 수정입니다. 이 표는 그라데이션·사진 위 글자·반투명 요소·최종 CSS 우선순위·실기기 확대를 모두 검사한 결과가 아니므로 페이지 전체 WCAG 적합성을 선언하지 않습니다.

## 3. 보호 기준과 변경 범위

원래 `docs/r4-spatial/protected-baseline.json`은 R4.1 기준 커밋과 바이트 동일 여부 **true**입니다. 보호 대상은 24개이며, 원래 기록 대비 실제로 바뀐 경로는 아래 6개뿐입니다. 나머지 18개는 SHA-256이 동일합니다. 별도 R42 보호 기준과 현재 파일의 해시 불일치는 **0개**입니다. 원래 기록을 새 값으로 덮어쓰지 않았습니다.

| 허용 변경 경로 | 실제 변경 범위 |
|---|---|
| `scripts/build-site.mjs` | review에서 R42 OG 이미지 URL 원점만 보정. production 판단, 회사·개인정보 공개 gate, canonical·og:url 보존. |
| `scripts/company-info.mjs` | 공통 footer의 브랜드 링크·이미지 마크업. 회사 정보·개인정보 설정값, 필드·링크·release 판정 로직은 유지. |
| `assets/css/brand.css` | 새 가로 로고 선택자·비율·작은 화면 크기와 max-width 해제. |
| `assets/home-r2/brand-symbol.png` | 새 W 심벌 이미지. |
| `favicon.ico` | 새 W의 16·32·48px 아이콘. |
| `apple-touch-icon.png` | 새 W 180×180 아이콘. |

이 6개는 **보호 목록 안의 변경 수**입니다. 홈페이지 HTML/JS, 새 CSS·사진·문서·테스트 등 이번 작업 전체 변경 파일 수를 뜻하지 않습니다. 실제 변경 경로 집합과 보호 기준은 [protected-baseline.json](protected-baseline.json)에 있습니다. 개인정보 원문, 회사 정보 설정, Netlify 설정·headers·redirects, sitemap·robots, 기존 폰트·이전 마사지 이미지 등 나머지 보호 항목은 바이트 동일합니다.

## 4. 별도 결과가 필요한 범위

브라우저에서 before 크롭의 인물·플랫폼 UI 제외, 느린 사진 로딩과 빠른 탭 전환, 패널 높이 변화, 좁은 화면의 헤더·footer, 포커스 이동을 확인해야 합니다. 실제 키보드·스크린리더·확대·reduced-motion 및 최종 네트워크 응답 검수는 코드 테스트만으로 대체하지 않습니다.

본 문서 작성자는 배포·운영 변경을 실행하지 않았습니다. Netlify Preview 주소·응답 확인, 실측 LCP/CLS/INP, Draft PR 상태와 브라우저 증빙은 루트 담당자의 별도 결과를 따릅니다. 이 문서는 운영 배포·main 병합·실DB·인증 변경을 승인하거나 완료했다고 주장하지 않습니다.
