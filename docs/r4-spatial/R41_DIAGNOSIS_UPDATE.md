# R4.1 · 첫 화면 진단 제안 정합성

작성일: 2026-11-03. 기준 커밋은 R4 제출 `42dc3213681be9cc1aab23c49ecb9cfee171df1d`입니다.

## 변경 목적과 실제 제공 범위

첫 화면 진단에서 알 수 있는 내용을 먼저 보여주고, 가격·신청 화면·준비되는 요청문을 같은 상품으로 맞췄습니다. 공개 범위는 **매장 1곳 · 공개 채널 1개 · 직접 써볼 개선안 1개 · 0원**입니다. 여러 채널을 함께 살피는 상세설계는 기존처럼 범위와 비용을 안내한 뒤 진행합니다.

한 가지 개선안을 다음 네 요소로 설명합니다.

1. 현재 화면 관찰: 사진·안내·다음 행동이 어떻게 보이는지.
2. 망설임 지점: 손님이 다시 찾거나 묻게 될 수 있는 지점. 고객 행동을 직접 측정했다는 뜻이 아닙니다.
3. 우선 개선안 한 가지: 바꿀 문구나 정보 배치.
4. 직접 적용할 순서: 실제 운영 정보 확인부터 변경 후 연결 확인까지.

이는 네 개의 별도 보고서나 다채널 종합 진단으로 범위를 넓힌 약속이 아닙니다. 계정 접속과 실제 화면 수정은 포함하지 않습니다. 실제 납품 내용을 동일한 범위로 작성할 수 있도록 [결과물 작성 양식](FIRST_DIAGNOSIS_RESULT_TEMPLATE.md)을 제공합니다.

## 화면과 요청문

- 질문: **손님이 어디서 망설이는지, 먼저 확인해 보세요.**
- 결과물 네 요소 → 첫 화면 진단의 0원·범위 → 살펴볼 화면 입력 순으로 구성했습니다.
- 헤더·Hero·모바일 CTA·진행 방식·접근성 이름을 첫 화면 진단으로 연결했습니다.
- `main-landing-r2.js`는 화면의 상품명·가격·범위·결과물 라벨을 읽어 카카오 요청문에 넣습니다. 별도 하드코딩 값이 어긋나는 경로를 줄였습니다.
- 요청문 생성 후에는 **아직 전송되지 않았습니다**라고 안내합니다. 사용자 직접 복사와 카카오 전송 구조를 유지합니다.
- 가상 매장 C의 결과물 예시를 실제 버튼 **예약 방법 확인하기** 및 안내를 펼치는 동작에 맞췄습니다.

## 내부 상품 시안과 공개 경계

종합 진단 기획안은 공개 상품과 별도입니다. 미확정 비교가격·체험 조건·월 정원은 공개 페이지에 넣지 않습니다. 내부 시안은 저장소·Netlify `dist/` 밖에서 별도 전달하며, 로컬 실행기의 `--concept` 옵션은 전달 ZIP의 `local-concept/`만 제공합니다. `noindex`를 비공개 조치로 취급하지 않습니다.

기존 실적 수치·원본 차트·Hero/Store C/FLOW 모션과 JS 소유권, 보호 파일 24개, 운영 release gate를 보존합니다. main 병합·운영 배포·DB·인증 변경은 범위에 포함하지 않습니다.
