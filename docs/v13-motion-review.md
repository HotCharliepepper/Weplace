## 보존한 기능과 구현 경계

4업종×2목적, 업종 변경 시 목적/화면/메모 초기화, 완료 이벤트의 시나리오당 1회 의미, 수동 복사/다운로드, 6문항 진단·미팅·고객/직원 로그인 경로를 보존한다. 모션 종료를 기다리지 않고 실제 선택 상태를 먼저 갱신한다. 빠른 반복 조작은 이전 애니메이션을 취소하고 마지막 선택을 유지한다.

새 모션 모듈이 없거나 Web Animations API가 실패해도 체험/스토리 탭은 작동한다. IntersectionObserver가 없으면 제목과 결과는 처음부터 정적으로 읽힌다. JS가 없으면 스토리 3개를 모두 표시하고 작동하지 않는 체험 컨트롤 대신 업종/미팅 안내 링크를 보여준다. 비교·스토리 영역의 높이는 minimum만 예약하므로 확대된 글이 잘리지 않는다.

회사/정책 승인 flag, FLOW 코드·DB·Identity·CRM·공개 승인, `_redirects`, 기존 analytics와 확장 이벤트 OFF는 수정하지 않았다. PR #5 가격·영문 초안을 가져오지 않았다. 운영 main과 production 배포는 유지한다.

## 재현 가능한 동작 기록

Preview: https://deploy-preview-8--weplace.netlify.app/
폭별 검토: https://deploy-preview-8--weplace.netlify.app/review/audience.html

1. 홈의 ‘손님 입장에서 우리 업종 살펴보기’를 누른다.
2. 요식업 → 가족 모임 목적 → 정리 후. 선택 색과 밑줄은 즉시 변경되고 예시 화면만 320ms 전환된다. 좋은 점·확인할 점·다음 행동이 이어진다.
3. 정리 전/후를 빠르게 반복하고 마지막에 정리 전을 누른다. 결과는 숨겨지고 화면/버튼/상태 안내는 모두 정리 전이어야 한다.
4. 카페·숙박·뷰티의 두 목적을 각각 확인한다. 업종 변경 직후에는 이전 결과와 메모가 남지 않아야 한다. 선택 답변은 자동 전송되지 않는다.
5. 비교 버튼에서 좌우 화살표, Home/End, Tab/Enter/Space를 확인한다. 페이지 전체의 화살표/스크롤은 가로채지 않는다.
6. ‘만드는 것’의 방문 전 → 현장 → 운영을 누른다. 탭에 둔 초점은 유지하고 같은 질문의 결과물만 전환된다. 좌우 화살표·Home/End로도 이동한다. Tab은 현재 패널로 이어진다.
7. 체험 아래 ‘움직임 줄이기’를 누른 뒤 전후 비교·스토리 탭을 반복한다. 효과 없이 같은 내용이 즉시 표시되어야 한다. 이 선택은 저장하지 않는다.
8. 폭별 검토 화면의 ‘자바스크립트 없이 보기’를 누른다. iframe의 sandbox에서 스크립트를 차단한다. 3개 제작물, 본문, 미팅과 정책 링크를 확인한다. 다시 켜면 새 홈 상태로 시작한다.
9. 업종 폴더를 열고 내부 링크에 초점을 둔다. 공개 API 갱신 뒤에도 열린 업종/초점을 유지하고 본문 등장 효과를 반복하지 않아야 한다. 승인 만료/오류에서는 기존 공개 수치가 사라져야 한다.

## 자동 검증

- 기준 43개 테스트 통과를 먼저 확인했다.
- 변경 후 `npm run verify`: **52/52 통과** (기존 43 + 모션 회귀 9), source 24 HTML / 763 참조 / 로컬 링크 결함 0, build 성공.
- 신규 검사: 반복 전환 취소/최종 상태/완료 1회, 업종 변경 중 무효화, OS 선호 변경 시 취소, 수동 감소와 저장 없음, 데이터 절약/저속 힌트, 애니메이션 API 부재·실패, 키보드·단일 tabpanel, no-JS 문서, 폴더 갱신 시 재생/초점 회귀.
- 신규 no-JS 테스트의 첫 실패는 여러 부모에 걸친 `:last-of-type` 선택자가 잘못된 noscript를 잡은 테스트 결함이었다. `#experience noscript`로 범위를 수정했다. 앱 오류로 기록하지 않는다.
- 기존 22개 회사/정책 확인 항목은 미확정 상태를 유지한다. 검토 빌드 성공은 운영 공개 승인이나 법적 준수 완료가 아니다.

## 성능 비용과 해석 한계

동일 파일 집합(홈 HTML, 고객 체험·업종 JS/CSS, 신규 모션 JS/CSS)의 로컬 바이트 비교:

| 항목 | 증가 |
|---|---:|
| 원본 바이트 | 18,203 bytes |
| 파일별 gzip 합계 차이 | 5,316 bytes |
| 새 요청 | 모션 JS 1개 + CSS 1개 |
| 추가 프레임워크/외부 자산 | 0 |

이는 로컬 gzip 추정이며 실제 네트워크 전송량·LCP·INP·CLS·Lighthouse 점수나 FPS 실측이 아니다. 레이아웃 높이 연속 애니메이션·상시 rAF 루프·스크롤 리스너를 추가하지 않았다. Save-Data/2G 힌트에서 효과를 생략하지만 실제 저가형 Android 성능을 검수한 결과는 아니다.

## 실제 브라우저 검수

적용 전 기준은 Chrome 390px iframe의 비교 버튼 40px, clientWidth=scrollWidth=375px, 가족 모임 정리 후 예시 높이 약 502px로 기록했다. 적용 전 화면을 캡처했다.

아래 항목은 최신 Netlify Preview가 준비된 뒤 관찰 결과로 갱신한다: 360/390/430/768/1024/1440px, 스토리 3탭, 8개 체험, 키보드, 수동 모션 감소, no-JS sandbox, 회사·정책·로그인 링크. 물리적 iOS/Android·OS 설정 전환·스크린리더·느린 네트워크/CPU·Lighthouse·실제 200% 브라우저 확대·5명 고객 관찰은 별도 검증 범위다.

## 소스와 되돌리는 단위

- `index.html`: 탭 의미 구조·설명·간결한 상태 안내·no-JS fallback.
- `assets/js/customer-discovery.js`: 기존 상태를 재사용하는 전환·키보드·스토리 탭.
- `assets/js/experience-motion.js`, `assets/css/experience-motion.css`: 독립된 효과/감소 설정. 두 자산을 제거해도 핵심 선택은 유지한다.
- `assets/js/industry-folders.js`, `assets/css/industry-folders.css`: native details 모션과 갱신 보호.
- `review/audience.html`: no-JS sandbox 검수 선택.
- `tests/v13-motion.test.cjs`: 기능적 실패·회귀 검사.

참고한 접근성 기준: [WAI-ARIA Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/), [MDN reduced-motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion). 이 구현/검수 기록은 전체 접근성 인증을 뜻하지 않는다.
