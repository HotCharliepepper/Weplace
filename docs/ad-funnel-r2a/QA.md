## 시각·행동 검수

- 첫 화면은 업종별 한 질문과 한 CTA, 이미지 1컷으로 정리했다. 기존 참고 이미지는 실제 고객 사례와 구분했다.
- 사진 선택은 좌석 사진, 길 선택은 입구 사진과 예시 약도, 예약 선택은 사진과 인원·시간 선택 UI를 실제로 전환한다.
- 비교는 같은 가상 매장 정보를 서로 다른 DOM 배치로 보여준다. 정리된 화면의 이미지는 좌석/음식으로 나뉘고 위치·주차·예약 정보가 한곳에 모인다.
- 관심 항목을 바꾸면 큰 화면, 비교 문장, 진단서 예시와 미팅 요청문이 함께 갱신된다. 클릭이 다음 섹션으로 스크롤을 강제하지 않는다.
- 한글 서체는 새 문장에 필요한 글리프를 포함한 로컬 서브셋으로 확인했다. 이미지 미로딩, 버튼 겹침, 44px 미만 핵심 터치 영역을 검사했다.
- 최종 캡처는 실제 Preview에서 생성했다. 데스크톱은 1363×936 CSS px 브라우저, 모바일은 390×844 CSS px iframe viewport다. 캡처 도구의 출력 축소와 모바일 프레임 영역 크롭만 적용했으며 UI를 합성하거나 수정하지 않았다.

## 데이터·보존 경계

진단은 **구성 미리보기**다. 실제 매장 분석·서버 접수·담당자 연락은 발생하지 않는다. 입력은 현재 문서 메모리에서만 쓰며 저장소·쿠키·URL·서버로 보내지 않는다. 입력 수정 시 이전 미리보기 완료 상태를 해제한다. 미팅은 희망 방식과 요청문 복사이며 실제 발송·일정 예약이 아니다.

기준 대비 기존 `index.html`, `ad-message.html`, `/experience/`, 히어로 소스·사례·FLOW/CRM·인증·DB·리다이렉트·회사/개인정보 승인 설정은 보존했다. 기존 빌드 스크립트와 보호 해시도 그대로 유지했다. `package.json`에는 기존 build 성공 후 정적 광고 경로를 복사하는 postbuild만 추가했다.

완료 시점 production deploy는 작업 전과 같은 `6ad8a7438ddf68ea7482fcd2`다. 새 빌드는 deploy-preview이며 운영 publish를 수행하지 않았다.
