# 개인정보 방침 및 운영 검토 — v1.2

확인 기준: 2026-10-19 KST. **처리방침 검토 초안과 코드 실사이며 적법성 보증 또는 운영 시행 승인이 아니다.** 실계정·CRM 값·공급자 운영 설정을 조회하거나 기존 개인정보를 변경하지 않았다.

## 공개 초안과 실제 처리의 구분

`/privacy/`는 로그인 없이 접근 가능한 검토용 초안이다. 시행일이 없으며 검색 제외 표시가 있다. 홈페이지·자가진단·미팅·내 매장 관리·공개 하위 페이지에서 연결된다. 법률 본문·입력 안내·회사 항목은 좌측 정렬을 유지한다. 실제 수집 동의나 서비스 약관으로 전용하지 않는다. 신규 동의 checkbox, 가입 처리, 자동 진단 전달, 실제 결제를 추가하지 않았다.

`docs/privacy-data-flow.json`과 `.md`는 홈페이지 4개 흐름과 FLOW 원본 11개 흐름의 통합 대장이다. 각 행에 목적, 정보주체, 항목, 필수/선택, 적법 근거, 경로, 저장 시스템, 접근자, 수탁/재수탁자, 국외 이전 국가·시점·방법, 보유기간·근거, 파기·백업, 권리요청 창구, 확인일과 소스 증거를 포함했다. 코드상 필드 존재와 실제 운영 수집을 구분했다.

| 관찰한 경계 | 초안에 반영한 내용 | 운영에서 확인할 것 |
|---|---|---|
| 홈페이지 체험·자가진단·미팅 준비 | 응답은 페이지 메모리. 명시적으로 복사·내려받기·인쇄한 사본은 사용자 환경 | 호스팅 기록, 실제 상담채널·직원 재입력, 쿠키/분석 설정 |

FLOW 원본 기준 SHA는 `29dace237c8a2ce2323a499409a81aa28a12a50b`다. 보호된 avatar URL의 `memberId`/version, 공급자 접속 로그는 신규 홈페이지 analytics 최소화와 다른 경계다. 모든 URL에 식별값이 없다고 주장하지 않는다. 로그아웃·연결 회수·사진 참조 해제·공개 철회는 일괄 탈퇴나 완전 파기가 아니다. 보유기간 자동파기/DB·Identity·Blobs 연쇄 삭제는 소스에서 발견하지 못했다. 이는 운영자의 별도 절차가 없다는 단정이 아니며 절차·설정 확인이 필요하다.

## 운영 적용 전 닫아야 할 항목

1. 최신 법인 정보·개인정보 책임/담당 부서·실제 권리요청 창구를 확인한다. 기존 공개 전화·이메일을 검증 없이 개인정보 전담 창구라고 선언하지 않는다.
2. 목적별 적법 근거·필수/선택·보유기간을 결정한다. 법정 보존이 적용되는 자료와 일반 운영 기록을 구분하며 임의로 1/3/5년을 쓰지 않는다.
3. Identity·Database·Blobs·Analytics·상담채널·Sheets의 실제 활성화, 계약 수탁/재수탁자, 국외 이전·로그·백업 설정을 확인한다. 비활성인 코드와 실제 처리 시스템을 구분한다.
4. 사진 교체/삭제·탈퇴·고객연결 회수·공개철회·백업 파기를 각각 구현/운영 절차로 정의하고 테스트한다. 실제 고객정보로 파기 실험하지 않는다.
5. 가입·프로필·사진 업로드·고객 의뢰의 수집 시점 안내와 최소항목을 확정한다. FLOW 담당자가 별도 로컬 검토 fixture를 준비했으며 현재 runtime 화면은 바꾸지 않았다. 자유기재에 제3자 개인정보를 넣지 않도록 하는 안내도 포함한다.
6. FLOW의 AuthGate/ClientPortal/SiteFooter 및 독립 Field Notes 번들에 승인된 동일 방침 링크와 법인 표시를 일치시킨다. homepage footer 추가만으로 FLOW 적용 완료가 아니다.
7. 권리요청 접수·본인 확인·처리/통지·사고대응과 안전조치 절차를 점검한다. 약관·개인정보 방침·개별 수집 고지를 분리한다. 서비스·계약 안내 링크를 확정 이용약관이라고 표시하지 않는다.
8. 승인자·시행일·이전 버전/중요 변경 고지 방식을 확정하고 법률 검토가 필요한 항목을 담당자에게 확인받는다. 실계정 분리, 접근성, 모바일 화면·외부 채널도 최종 검수한다.

## 빌드 경계와 배포 승인

`config/privacy-release.json`은 현재 draft이며 13개 운영 확인 flag가 모두 false다. 회사정보도 releaseApproved=false다. `scripts/company-info.mjs`는 고정 필수 키의 존재·literal true·확인값/증거·유효 승인일/시행일을 검사한다. 키를 삭제하거나 빈 객체를 넣어 검사를 생략할 수 없다.

`CONTEXT=production npm run build` 또는 `npm run build -- --production`에 해당하는 직접 스크립트 호출은 미확정 상태에서 산출물 삭제/복사 전에 실패한다. 실제 수동 명령은 `node scripts/build-site.mjs --production`으로 확인할 수 있다. production HTML은 `data-policy-state="approved"`를 명시하고 draft 표식이 없어야 한다. 회사/방침 config 승인만으로 초안 HTML이 통과하지 않는다. 현재 이 경계는 운영 배포 의도를 검증하는 빌드 보호 장치이며 Netlify 권한을 대체하지 않는다.

검토 빌드는 모든 HTML과 산출물 `_headers`에 noindex/nofollow를 적용한다. 원본 `_headers`의 운영 전역 robots 규칙은 변경하지 않는다. 초안 자체는 승인 전 noindex를 유지한다. 검색 제외는 비밀보장 수단이 아니므로 개인정보·내부 고객 증거는 검토 페이지와 공개 저장소에 넣지 않는다. docs/config/tests는 배포되지 않으며, `/privacy/`의 사람용 초안만 공개 경로에 포함된다.

최종 승인 후 책임자가 검증한 데이터·방침 본문·운영 UI를 함께 갱신하고 production build gate를 통과시킨다. 그래도 PR 병합/운영 배포, 실데이터 변경, 자동 개인정보 저장, 실제 결제 활성화는 사용자의 별도 최종 승인 대상이다. 이번 작업에서 그 행위를 하지 않았다.
