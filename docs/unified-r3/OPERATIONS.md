# 광고와 문의의 운영 경계

운영 홈페이지: https://withweplace.kr/#experience
새 검토 경로: Draft origin + `/unified-r3.html`
내부 비교 허브: Draft origin + `/review/unified-r3.html`

기존 `/go/dining/`, `/go/stay/`, `/go/wellness/`, `/go/local/` 및 `/ad-funnel.html`의 코드·리다이렉트 계약은 바꾸지 않았다. 새 통합 경로는 `?ad=dining|stay|wellness|local`에서 동일한 업종 질문을 보여주고 공통 체험으로 연결한다. 검토 허브의 UTM 예시는 발송 승인된 캠페인이 아니다.

기존 공개 채널 `https://pf.kakao.com/_mxbexhX` 사용. 문의문은 입력을 .value/.textContent로만 처리하고 메모리 안에서 생성한다. 입력·선택 변경 시 기존 문구는 폐기 후 재생성한다. 복사 버튼 성공은 카카오 발송·접수·미팅 확정이 아니다. 브라우저가 복사를 차단하면 textarea를 선택하고 직접 복사하도록 안내한다.

| 단계 | 실제 확인할 기록 | 이번 구현 |
|---|---|---|
| 광고 클릭 | 유입 URL·허용된 집계 기준 | 경로만 검토, 신규 분석 수집 꺼짐 |
| 문의 접수 | 카카오 대화에 실제 수신된 문의 | 사용자의 직접 전송 필요, 자동 접수 없음 |
| 진단서 전달 | 담당자가 완성한 문서와 실제 전달 기록 | 구성 예시만, 생성·전달 자동화 없음 |
| 미팅 확정 | 양측이 합의한 시간·방식 | 일정 문의문만, 자동 확정 없음 |

담당자가 카카오 수신 확인 → 범위·일정 안내 → 필요한 경우 기존 FLOW 수동 등록 → 실제 진단서 전달 → 미팅 합의를 별도 기록해야 한다. 이 절차를 수행했다고 주장하지 않는다.

UTM은 기존 4개 키에 ASCII 영숫자/underscore/hyphen 1–80자 제한을 적용해 같은 origin의 상세 링크에만 전달한다. 매장명·지역·전화·진단 내용은 URL/GA4/로그/저장소로 보내지 않는다. 새 분석 이벤트·추적 태그 없음.

실제 iOS Safari·Android Chrome·카카오 인앱에서 열기, 뒤로 가기, 복사, 카카오 채널 전환, 직접 붙여넣기 직전까지 확인 후 광고 발송 승인 필요. 실제 메시지 전송·광고비 집행은 이번 작업 밖이다.
