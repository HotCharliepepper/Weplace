## 유지된 동작

- 원문 지시서의 **4업종·업종별 2목적, 전체 8개 목적**을 검증했다. 업종별 8목적, 전체 32개로 확장한 것이 아니다.
- 업종 → 목적 선택 시 정리 전 화면 → 정리 후 선택의 세 단계와 좋은 점·확인할 점·다음 행동이 유지된다. 같은 상황을 반복 비교해도 완료 신호를 중복 생성하지 않는다.
- 체험을 마친 뒤 업종을 바꾸면 이전 결과·목적·내보내기가 무효화된다. 예전 업종의 메모가 새 맥락으로 복사되지 않는다.
- 6문항 진단, 모름/긍정/누락 응답 처리, 명시적인 복사·다운로드, 미팅 준비와 인쇄가 유지된다.
- 업종은 고정 허용 목록으로만 URL에 전달한다. 임의 query·목적·답변·연락처를 결과 링크나 분석 payload에 복제하지 않는다.
- 진단·미팅 선택은 CRM 접수·예약 확정·계약·결제가 아니다. 해당 입력 동작에서 네트워크·저장·추적 호출이 발생하지 않는 것을 계측했다. 공개 업종 API 조회, 호스팅 접속기록, 기존 운영 GA는 이 문장과 별개다.
- 운영 호스트의 기존 GA 이벤트만 허용하고, 신규 이벤트는 OFF다. preview·진단·미팅·검수 경로의 계측 스크립트는 비활성이다.
- 메뉴의 ARIA 상태, Escape 시 초점 복귀, 외부 클릭/화면 폭 변경 시 닫기, 업종 폴더에서 체험으로 초점 이동, reduced-motion의 `auto` 스크롤 분기가 유지된다. 이는 DOM 동작 검사이며 화면 가독성 실측이 아니다.
- `/client`, `/client/*`, `/team`, `/team/*`와 두 공개 API 프록시의 목적지·상태 코드는 원본 계약과 일치한다.

## 검수 중 수정한 승인 차단 문제

**누락된 항목으로 승인을 우회할 수 있던 검사**를 발견해 담당자에게 수정 요청했다. 최초 구현은 config에 존재하는 필드만 순회하므로 필수 키를 삭제하면 그 항목을 검사하지 않았다. 현재는 고정된 필수 회사 필드와 개인정보 확인 목록을 검사한다. 필드 삭제·빈 객체·문자열 `"true"`·잘못된 승인일/시행일을 넣는 회귀 테스트가 모두 실패를 올바르게 감지한다.

**정책 HTML의 인용부호에 의존하던 초안 검사**도 수정했다. 현재는 명시적인 승인 상태가 없거나, 따옴표·대소문자·공백을 바꾸어도 draft 표기가 남으면 운영용 빌드를 차단한다. config만 가상 승인 상태로 바꾼 격리 테스트에서도 초안/미분류 HTML은 배포 파일을 만들기 전에 거부된다.

테스트에 사용하는 승인 값·검토자·증거는 가상 fixture다. 실제 설정의 `releaseApproved`는 false이며 운영 승인을 생성하지 않았다. 승인 gate는 제출된 증거 기록의 완결성을 검사할 뿐, 서류의 진위나 법률 적합성을 자동으로 보증하지 않는다.

## 사례·개인정보·브랜드 경계

- 홈의 새 작업 장면은 가상 구성 예시이며 실제 제작·납품 사례로 표시하지 않는다. 설마중 이름·자료·성과·`/cases/seolmajung/` 링크를 공개 파일에 넣지 않았다.
- `/review/case-layout.html`은 실제 고객 자료가 없는 일반 구조 fixture다. 제안·제작·납품·사용 중을 구분하고 증거 미입력을 명시한다. noindex는 접근 통제가 아니므로 이 페이지에 실제 미승인 고객 자료를 나중에 넣어서는 안 된다.
- 실제 `dist`에서 사례 실명·격리 테스트용 내부 증거/검토 토큰·일부 알려진 비밀키 패턴을 검사해 일치 항목이 없었다. `/review/integration.html`의 `SYNTHETIC_PRIVATE_*`는 기존 공개 API 오류 검수를 위한 가짜 값으로 확인했다. 문자열 검사만으로 모든 비밀 유출 가능성을 보증하지 않는다.
- 회사정보·정책 config와 내부 검수 문서는 배포 파일에서 제외된다. 공통 footer는 빌드 시 렌더링하며 브라우저에서 회사 config를 조회하지 않는다.
- 개인정보처리방침은 아직 검토 초안이다. 계정 설정·위탁/이전·보유/삭제·담당 창구 등 미확인 내용을 완성된 운영 사실로 승격하지 않는다. 현재 설정과 HTML로는 production 빌드를 통과할 수 없다.
- Mashcore 연결은 콘텐츠 링크다. 계정 통합·고객 기록 복제·상담 인입·SSO를 추가하지 않았다.

## 남은 검수와 승인

1. 실제 브라우저의 360/390/430/768/1024/1440px 가독성·긴 문장·고정 CTA·footer·개인정보 페이지 확인 및 캡처는 root의 별도 브라우저 검수 기록으로 판단한다. 이 문서에는 실행하지 않은 시각 결과나 Lighthouse 수치를 적지 않는다.
2. 최신 사업자등록증·담당자 확인과 개인정보 처리 운영 확인이 필요하다. 공통 footer의 기존 법인 표기는 최신 증빙 확인 완료를 뜻하지 않는다.
3. 설마중 실제 사례는 완료·사용·기여·공개권한·가림·인용 근거를 확보하고 승인한 뒤 공개한다.
4. FLOW 실계정 간 권한 분리·연결 해제·세션 만료 검수는 이번 정적 홈페이지 테스트로 대체되지 않는다. 운영 DB/인증을 공유하는 preview도 자동으로 격리된 테스트 환경이 되지 않는다.
5. 운영 main 병합·배포, 법률 문서 확정 게시, 신규 수집/분석 활성화, 계약·결제와 고객 데이터 변경은 사용자 최종 승인 전 실행하지 않는다.
