## 2. 글로벌 두 방향의 분리

| 구분 | 서비스를 검토하는 운영자 | 매장을 선택하는 손님 | 대응 페이지 |
|---|---|---|---|
| 한국 매장의 외국인 손님 유치 | 한국에 있는 매장 운영자 | 한국 방문·체류 중 정보를 찾는 외국인 손님 | `/global/international-visitors-korea/` ↔ `/en/global/international-visitors-korea/` |
| 해외 매장의 한국인 손님 유치 | 해외 현지 매장 운영자 | 해외 방문을 준비하거나 현지에 있는 한국인 여행객 | `/global/korean-visitors-overseas/` ↔ `/en/global/korean-visitors-overseas/` |

전체 안내는 `/global/` ↔ `/en/global/`로 연결한다. 각 언어 페이지는 실제 짝에만 상호 `hreflang`을 붙이고 자기 canonical을 갖는다. 언어·국가 추정에 따른 자동 이동이나 국가·상담 정보를 FLOW로 보내는 기능은 추가하지 않는다. 해외 사무실·모든 국가의 수행 능력·모든 언어 응대를 암시하지 않는다.

## 3. 검수에서 발견하고 수정한 결함

**공개 기록 만료 시 키보드 초점 유실**

- 원인: 승인된 관리 현황의 펼침 버튼·기록 링크에 초점이 있을 때 API 재조회나 만료로 해당 컨트롤이 제거되면, 복구할 같은 컨트롤이 없어 초점이 문서 본문으로 빠짐.
- 수정: 렌더 전에 초점이 속한 업종을 기억하고, 기존 컨트롤이 없어진 경우 같은 업종의 summary로 복귀. 유효한 재조회에서는 원래 컨트롤을 우선 복구.
- 검증: 새 `v14-disclosure.test.cjs`에서 정상 재조회·만료·후속 조회 실패를 검사. 이전 수치·기록은 숨기고 보조 설명의 열린 상태와 안전한 초점 이동을 확인.

**잘못된 테스트 가정의 제외**

과거 업종 별칭 페이지의 본문과 canonical이 완전히 같아야 한다는 가정은 기존 설계와 맞지 않았다. 안내 배너·하위 업종명·독립 경로 차이를 제품 결함으로 처리하지 않았다. 테스트는 실제 업종 카드에서 연결되는 페이지의 질문·그림·근거·CTA 및 보호 경계를 확인하도록 한정했다.

## 5. 최종 승인 전 유지할 항목

- **운영 반영:** main 병합과 Netlify production 배포.
- **글로벌 서비스 범위:** 대상 국가·업종·제공 언어·응대 인력·제작물·방문/현장지원·운영 주기·지원 시간.
- **법인·개인정보:** 최신 회사 증빙, 수집 항목·목적·보유/삭제·위탁·국외 이전·권리 행사 등 22개 기존 확인 항목 및 글로벌 확장 영향. 운영 담당자·전문가 확인 전 확정하지 않음.
- **고객 자료:** 실명·사진·사례·사용 화면·성과 자료의 제작/납품/실사용 상태와 공개 범위.
- **수치:** 원본·단위·분모·기간·필터·해석·공개 승인. 조회 수치와 실제 계약/매출을 구분.
- **데이터·분석:** FLOW 실제 데이터·권한·스키마 변경, 신규 추적, 개인정보 자동 저장·전송, 브랜드 간 계정/상담 기록 공유.
- **상거래:** 실제 계약 조건, 국가별 계약·정산, 청구·결제·PG 활성화.

Preview의 noindex는 검색 노출을 제한하는 표기이며 접근 통제가 아니다. 위 항목의 승인 전 고객 원본·개인정보를 Preview에 올리지 않는다.

## 6. 수정·되돌림 기준

현재 기준은 v1.3 기능을 유지한 후속 패치다. 문제 발생 시 v1.4 변경 중 원인이 있는 부분만 별도 커밋으로 수정하거나 되돌린다. 업종 선택·정리 전/후·6문항 진단·미팅·고객 로그인·모션 감소 기능 전체를 과거 버전으로 덮어쓰지 않는다.

글로벌 안내를 철회해야 한다면 홈 진입 링크, 해당 6페이지, sitemap의 같은 6개 항목, 글로벌 스타일과 빌드 복사 범위를 함께 검토한다. PR #5의 루트 영문 페이지나 기존 FLOW 경로로 자동 대체하지 않는다. 변경 뒤 로컬 링크·언어 짝·빌드 승인 경계를 다시 확인한다.

비교표를 조정할 때는 예시 원본과 두 화면의 일치를 유지하고, 펼침/접기와 상태 초기화 검사를 함께 실행한다. 공개 카드 갱신을 수정할 때는 승인 만료·이전 응답 역전·초점 복귀 검사를 우선한다.
